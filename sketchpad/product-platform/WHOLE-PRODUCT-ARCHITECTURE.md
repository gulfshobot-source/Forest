# Forest Whole-Product Architecture — Provisional Map

**Status:** non-canonical synthesis / promotion candidate  
**Purpose:** map the larger Forest product without collapsing experimental layers into one app or prematurely promoting ontology.  
**Source basis:** existing Forest runtime, substrate experiments, memory ecology, AI-mycelium thread, and the Adaptive Inquiry Workspace / ThreadMap product map supplied by the user.

## Product thesis

Forest is a vertically integrated AI production environment that converts human intent and heterogeneous material into persistent, inspectable, executable, and reality-connected work.

The human-facing spatial inquiry workspace is not the whole product. It is the primary experiential/control layer over deeper persistent, connective, memory, reasoning, execution, and reality-interface systems.

## Primary product surfaces

### 1. Capture surface

Voice, typing, screenshots, files, links, camera, imports, clips, connected-system events, and rapid sparks enter without requiring immediate classification.

### 2. Inquiry workspace

The user can converse naturally while AI proposes reversible thread, question, insight, claim, assumption, decision, source, artifact, task, experiment, person/role, and domain objects.

### 3. Spatial navigation

The workspace projects canonical structure into zoomable maps, focus views, timelines, dependency views, contradiction views, evidence views, and path replay. Visualization is a projection over canonical state, never a second authoritative database.

### 4. Artifact studio

Selected graph regions can become documents, plans, code architectures, curricula, diagnostic flows, research programs, experiments, dashboards, or other domain artifacts while retaining provenance back to source objects.

### 5. Production console

Users can inspect current objective, Production Warrant, selected work, dependencies, tests, failures, evidence, completion ledger, blockers, permissions, and next leverage. This is the human window into the autonomous runtime.

### 6. Reality bridge

Authorized connectors and executors turn internal plans into external actions and ingest external state back into Forest with explicit authority and provenance boundaries.

## Core object families

The product should avoid one flat universal node type. Current provisional families are:

- **Capture objects:** raw message, transcript segment, file, image, link, event, spark.
- **Inquiry objects:** thread, question, insight, claim, assumption, contradiction, uncertainty.
- **Decision objects:** decision, option, rationale, constraint, permission, human gate.
- **Production objects:** objective, task, dependency, warrant, procedure, test, measurement, failure, recovery action.
- **Evidence objects:** source, observation, experiment, result, provenance record, confidence/authority state.
- **Artifact objects:** document, code, plan, model, visualization, release, export.
- **World objects:** person/role, organization, asset, system, domain entity, external state.
- **Structural objects:** collection, branch, relation, cross-link/vine, view, projection, version/delta.

These are provisional object families. The deeper AI-mycelium `collection / catalog / character / cellular` formulation remains unresolved and must not be collapsed into this list by convenience.

## Relationship grammar

Relationships are first-class and typed. Useful initial classes include:

- structural: contains, member-of, continues, deepens, generalizes, narrows;
- epistemic: supports, challenges, contradicts, exemplifies, evidences, assumes, unresolved-by;
- causal: causes, contributes-to, prevents, enables;
- production: depends-on, requires, implements, tests, measures, produces, replaces;
- temporal: precedes, supersedes, valid-during, derived-from-version;
- authority/provenance: sourced-from, proposed-by, confirmed-by, rejected-by, authoritative-for;
- cross-domain: analogous-to, application-of, reusable-in, vine-to.

Every important relationship should preserve why it exists, its source, authority state, and whether it is provisional or confirmed.

## Human/AI authority model

AI may propose structure aggressively enough to be useful, but proposed structure is not automatically authoritative.

States should remain distinguishable:

`raw → proposed → inferred → observed → verified → authoritative`

with rejection, invalidation, supersession, and uncertainty preserved rather than erased.

The user can accept, rename, split, merge, park, reject, or defer organization. Raw source material remains reachable even after synthesis.

## Memory model

Memory is an ecology, not one store. The product needs at least:

- ephemeral/session context;
- thread/project working memory;
- durable canonical knowledge;
- user-confirmed preferences;
- procedural/skill memory;
- failure/recovery memory;
- uncertainty/contradiction memory;
- temporal/trajectory memory;
- external-state mirrors and caches;
- capability/connector memory.

External memory systems may accelerate or derive views, but they do not silently overwrite canonical truth.

## Runtime relationship

The verified runtime kernel is the first executable nervous-system layer, not the finished product. Its job is to preserve continuation semantics across every later subsystem:

`RECOVER → UNDERSTAND → RECONCILE → CLASSIFY → CONNECT → BUILD → PERSIST → VERIFY → VISUALIZE → LEARN → IDENTIFY NEXT LEVERAGE → CONTINUE`

The control surface should eventually expose this loop without forcing the user to micromanage it.

## Product progression

### Phase A — Verified production kernel

Persistent state, selection, execution boundary, recovery, validation, telemetry, warrant regeneration, CI verification.

### Phase B — Whole-product model

Reconcile product stack, object model, relationship ontology, authority states, cross-layer contracts, and promotion boundaries.

### Phase C — ThreadMap / Inquiry MVP

Import/live conversation, thread extraction, editable ledger, raw-message linkage, typed relations, focus mode, graph view, path replay, artifact generation, undo/history.

### Phase D — Live adaptive workspace

Voice/capture, provisional branch suggestions, mobile navigation, drag/drop, memory controls, project spaces, adaptive view composition.

### Phase E — Production integration

Connect selected map regions to Forest runtime tasks, tests, artifacts, permissions, human gates, and external executors.

### Phase F — Universal modular environment

Domain worlds, reusable packs, multi-agent orchestration, connector fabric, extensible visual grammars, collaboration, APIs, and developer platform.

### Phase G — Recursive self-improvement

Forest measures and improves retrieval, representation, context loading, selection, reuse, runtime cost, failure recovery, interface composition, and its own architecture under explicit authority and verification constraints.

## Cross-layer invariants

1. One authoritative canonical state; many projections.
2. Raw evidence survives synthesis.
3. No false completion without explicit evidence.
4. No silent authority escalation from AI inference or external memory.
5. Stable references and deltas preferred over repeated state transmission.
6. Reusable generative structure preferred over duplicated representation.
7. Every external action crosses an explicit permission/authority boundary.
8. Failed experiments remain usable evidence.
9. Human gates occur only where judgment, permission, rights, or physical action are irreducible.
10. Domain-specific systems grow on portable substrate rather than redefining the substrate.
11. Visualization must remain reconstructable from underlying state.
12. Forest must be able to improve Forest without bypassing its own verification rules.

## Key unresolved design questions

- What is the smallest canonical object/relationship substrate that can express the product without prematurely freezing the AI-mycelium cellular model?
- Which relationships deserve first-class semantics versus extensible domain-defined labels?
- How does one object participate in multiple collections/scales without duplicated canonical homes?
- How should user-private thought graphs, project graphs, team graphs, and public artifacts intersect?
- What exact promotion contract moves provisional AI structure into canonical state?
- Which parts of the World Engine are deterministic projections and which may be AI-composed?
- How should path replay distinguish historical sequence from reconstructed causal/semantic reasoning?
- What is the minimal mobile spatial grammar that remains usable at Forest scale?
- How should the runtime choose between research, coding, retrieval, connector action, simulation, and human gating executors?
- Which meta-metrics are safe and useful for recursive self-optimization?

## Promotion path

This map should not be copied wholesale into canonical Forest. Reconcile it against existing canonical architecture object-by-object and promote only components that:

- explain or connect existing canonical structures better;
- eliminate duplication or ambiguity;
- preserve provenance and authority boundaries;
- survive implementation/user-validation pressure;
- create an executable or navigable capability the Forest currently lacks.

Proposed next bounded task: **whole-product architecture reconciliation** — compare this map against canonical Forest structures, identify duplicates/conflicts/missing contracts, then promote only validated architecture relationships.

# Whole-Product Architecture Reconciliation

Status: completed reconciliation record; source for selective canonical promotion  
Date: 2026-09-10

## Scope

Compared the provisional `WHOLE-PRODUCT-ARCHITECTURE.md` responsibility stack against the authoritative structures in `gulfshobot-source/the-forest`, especially:

- `FOREST.md`
- `architecture/CANONICAL_DATA_MODEL.md`
- `architecture/FOUNDATIONAL_SUBSTRATE.md`
- `architecture/FOREST_CONTROL_SURFACE_TARGET.md`
- `architecture/AGENTIC_HARNESS.md`
- `architecture/WORLD_ENGINE.md`
- `architecture/REALITY_INTERFACE_AND_MANIFESTATION.md`

The purpose was not to promote the provisional stack wholesale. It was to find which relationships are already supported, which concepts duplicate canonical homes, which remain experimental, and which cross-layer contracts are actually missing.

## Duplicate-home findings

The provisional stack would create duplicate canonical homes if adopted literally in at least five places:

1. `Canonical World Model` would duplicate the Canonical Data Model.
2. `Intelligence / Agentic Harness` would duplicate the existing Agentic Harness.
3. `Representation / World Engine` would duplicate or blur the World Engine, Cognitive Visualization, and Control Surface boundaries.
4. `Reality Interface` would duplicate the existing Reality Interface architecture.
5. `Autonomous Production Runtime` would incorrectly elevate one current implementation into a new source-of-truth architectural tier.

Resolution: preserve the provisional stack as a responsibility lens, but map responsibilities onto existing canonical homes.

## Tensions/conflicts surfaced

### 1. Linear stack vs recursive composition

The 11-layer diagram is useful for orientation but conflicts with the Forest's recursive/tree/vine/substrate composition if interpreted literally as a strict hierarchy.

Resolution: canonicalize cross-system composition, not the 11-layer hierarchy.

### 2. Mycelium as a named layer vs existing connective mechanisms

Relationships, dependencies, vines, navigation continuity, capability routing, and provenance already exist canonically. The deeper `cellular / collection / catalog / character` hypothesis may explain them later, but has not yet earned authority.

Resolution: map known connective responsibilities to existing homes; keep deeper mycelium research quarantined.

### 3. Workspace object taxonomy vs canonical object classes

The ThreadMap list (`thread`, `question`, `insight`, `claim`, etc.) may be useful product semantics, but it is not yet proven to be the canonical universal object ontology.

Resolution: treat these as experimental semantic/domain classes that may reference or extend canonical objects without replacing the Canonical Data Model.

## Promotion candidates accepted

Ten composition relationships had sufficient support in existing canonical architecture and were promoted into `gulfshobot-source/the-forest/architecture/WHOLE_PRODUCT_MAP.md`:

1. Control Surface is a projection/operating surface, not truth storage.
2. Foundational Substrate binds existence and navigation continuity.
3. Agentic Harness operates over canonical state rather than owning it.
4. World Engine is replaceable semantic/spatial embodiment.
5. Reality Interface is the external verified action/observation boundary.
6. Trees are domain homes and vines are cross-domain relationships.
7. External runtimes/memories/renderers/connectors remain replaceable until deliberately promoted.
8. External action must return evidence before canonical reconciliation.
9. Representations are reconstructable projections over authoritative state.
10. Phase/subsystem completion must not imply global Forest completion.

## Promotion candidates rejected/deferred

Seven notable items remain non-canonical:

- ThreadMap as final product identity.
- Adaptive Inquiry Workspace as a new source-of-truth layer.
- the 11-layer stack as physical/storage hierarchy.
- universal flat workspace object taxonomy.
- generative/cellular substrate ontology.
- collection/catalog/character semantics.
- any particular memory provider, model, renderer, agent framework, or connector as foundational authority.

## Missing cross-layer contracts

Reconciliation exposed seven high-leverage interfaces that are more important than inventing additional layers:

1. canonical object -> runtime task
2. runtime observation -> canonical reconciliation
3. Control Surface intent -> Harness warrant
4. substrate locus -> minimum-sufficient context assembly
5. Reality capability state -> executable adapter + verification
6. experimental inference -> canonical promotion
7. lab repo -> canonical repo synchronization

These contracts are now the next architectural work queue.

## Result

The larger product no longer needs a second architecture hierarchy. Forest already contains most of the necessary canonical subsystem homes. The highest-leverage work has shifted from naming layers to defining the interfaces that let those existing systems compose reliably.

Next bounded task: define the **cross-layer contract set**, beginning with canonical-object-to-runtime-task and runtime-observation-to-canonical-reconciliation because together they close the executable loop between authoritative knowledge and the verified runtime.
